# 先に読んでほしい規則

CSSの対応状況を見る前に知っておいてほしい、**全体に効く5つの規則**です。
「なぜかスタイルがまったく効かない」の原因はたいていこのどれかです。

対応表そのものは[プロパティ対応表](properties.md)と
[セレクタ・値・at-rule](selectors.md)にあります。

## 凡例

| 記号 | 意味 |
| - | - |
| ✅ | 対応。仕様の主要な値・挙動をカバーしている |
| ⚠️ | 条件付き対応。受け付ける値が仕様の一部に限られる、または挙動が簡略化されている(備考に条件を書く) |
| ❌ | 非対応。宣言はパースエラーとして捨てられる |

## 1. 非対応の値が1つでも混じると、その宣言は丸ごと無視される

パーサは「プロパティ名 → 値」を1宣言単位で処理し、値の末尾に解釈できない
トークンが残った時点でその宣言をエラーとして捨てます。捨てられるのはその1宣言
だけで、同じルール内の他の宣言や後続のルールには影響しません。

```css
p {
  margin: 10pt;                 /* ❌ pt は非対応 → この宣言だけ無視される */
  background: #fff padding-box; /* ❌ background-clip 部分が非対応 → 宣言ごと無視(背景色も付かない) */
  color: red;                   /* ✅ 効く */
}
```

## 2. `!important`は非対応 — 付けた宣言は無視される

優先度が上がらないのではなく、**宣言そのものが捨てられます**。
`color: red !important;`と書くと色指定自体が無くなるため、移行時は要注意です。

## 3. グローバルキーワード(`inherit`/`initial`/`unset`/`revert`)は非対応

どのプロパティでも受け付けません。`color: inherit`のような宣言は無視されます
(継承プロパティの通常の継承自体は仕様どおり動作します)。

## 4. 長さの単位は`px`/`em`/`rem`と`%`のみ

`pt`/`pc`/`cm`/`mm`/`in`/`ex`/`ch`/`vw`/`vh`等は非対応です。`0`は単位なしでも
書けます(仕様どおり)。角度は`transform`でのみ使え、`deg`/`rad`/`grad`/`turn`に
対応します。

> **CLIオプションとは単位の扱いが違います。** `--margin-top 20mm`のような
> コマンドラインオプションは`mm`/`cm`/`in`/`pt`/`px`を受け付けます。制限が
> あるのはCSSの中だけです。

詳しくは[セレクタ・値・at-rule](selectors.md#値単位関数)を参照してください。

## 5. カスケードの優先順位

オリジン(UAスタイルシート → レガシー表示属性 → 作者CSS) → 詳細度 → ソース順、
の順で解決します。`style`属性は作者CSS扱いです。ユーザーオリジン・`!important`は
ありません。

CLIの`--user-style-sheet`で渡したCSSは、UAスタイルシートより強く、著者CSSより
弱いものとして扱われます。
